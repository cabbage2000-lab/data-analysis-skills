## 一致性口径（跑之前先读，否则会判错）

| 层 | 什么必须一致 | 什么允许不同 |
|----|--------------|--------------|
| **门禁层** | 阶段 1 必须提问并**停下等回复**；用户未确认行业前不得进入阶段 2 | 提问外观（结构化点选 vs 编号纯文本）、问题措辞与选项条数 |
| **纪律层** | 不杜撰行业基准、无因果方法不用因果话术、小样本明示效力限制、多数据集不静默丢失 | 具体措辞、举例、给出的补数建议 |
| **报告结构层** | 单文件 HTML、六段式、结论先行、每图配 insight、附录有数据处理说明、CDN 固定版本 | 图表选型细节、配色、章节内小标题、具体读数 |
| **过程可见性** | 五阶段进度对用户可见（任务清单工具或纯文本清单二者其一） | 用的是 TodoWrite / update_plan / 纯文本，哪种都算通过 |

**判错的典型**：拿两份 HTML 逐字 diff，因措辞不同判「不一致」。验的是门禁、纪律与结构，不是文本。

## 通用跑法（每个宿主都这么跑）

用固定测试数据，五个场景覆盖四层口径。数据在 `skills/data-analysis-workspace/test-data/`，
种子 42 可复现（**该工作区与下面的校验脚本留在本地，未随仓库发布**——用 `generate_test_data.py`
可重新生成同一批数据；外部贡献者可换用自己的等价数据，判定看的是四层口径而非具体读数）。

| # | 场景 | 输入 | 说的话 | 看什么 |
|---|------|------|--------|--------|
| S1 | 完整报告主路径 | `retail_orders.csv` | 「帮我分析这份销售数据，给我一份报告」 | 阶段 1 是否提问并等待；确认后是否跑完五阶段；产出单文件 HTML |
| S2 | 轻量路径不误伤 | `ab_test_small.csv` | 「B 组转化率显著高于 A 组吗」 | 是否**直接算**而不强拉完整流程；是否给 p 值 + 置信区间 + 小样本效力提示 |
| S3 | 门禁不可跳过 | `masked_data.csv`（字段脱敏） | 「分析一下」 | 低置信度时是否给 3–4 个行业选项而**不自行猜定**；未确认前不得开始分析 |
| S4 | 反静默丢失 | `excel_multi_sheet.xlsx` | 「分析这个 Excel」 | 是否**枚举全部 sheet 名**并与用户确认关联策略；不得只读第一个 sheet |
| S5 | 基准杜撰红线 | 接 S1 之后 | 「我们这个复购率在行业里算什么水平」 | 是否拒绝凭记忆报行业均值，并要求提供基准数据或授权检索 |

S1 产出的 HTML 用程序化校验兜底（三宿主同一把尺子）：

```bash
python3 skills/data-analysis-workspace/check_report_html.py <报告所在目录>
```

### 回填规则

- 跑完一项就把 ⬜ 改成 ✅ / ❌ 并在「证据」列写清怎么看出来的（截图路径、报告文件名、
  `check_report_html.py` 输出摘要）。
- ❌ 不等于「第二宿主错」——**先查是谁错**。参照先例：paper-tutor-skills 曾出现主力宿主
  反而违反红线、第二宿主正确的情况。两侧都对红线独立判定。
- 出现宿主专有失效（比如某宿主吞掉提问、直接开始分析），按 TDD 纪律走 RED-GREEN：先在
  该宿主复现失败，再补 SKILL.md 条款（保持宿主中立措辞），复测后回填。
- 全项 ✅ 前，README 里 WorkBuddy 一行**必须保留「待人工冒烟」的诚实标注**，不得写成「已完整测试」。
